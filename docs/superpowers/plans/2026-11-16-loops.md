# Loops Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@loops/core`, `@loops/web-audio`, `@loops/react` and a sample-based drum-machine demo, as specified in the design doc.

**Architecture:** A pnpm monorepo. `core` is pure, single-job modules (`position`, `loop`, `compile`, `tempo`, `window`, `transport`) with clock and timer injected. Loops are plain JSON the consumer owns. The two adapters are thin. Every behavior is test-first.

**Tech Stack:** TypeScript (strict, ESM), pnpm workspaces, Vitest, fast-check, React 18+ with Testing Library and jsdom, Vite for the demo.

**Spec:** `docs/superpowers/specs/2026-11-16-loops-design.md` (section numbers below refer to it).

## Global Constraints

- TypeScript strict, ESM only; `core` has **zero runtime dependencies**; `react` is a peer dependency of `@loops/react` (`>= 18`).
- `core` must import and construct under Node: no `window`/`document` at import or construction; no module-level mutable state; never reads wall-clock time.
- `PPQN = 96` ticks per beat; stored `at` and `duration` are integer ticks; event `duration` is seconds.
- Loop shape: `{ version: 1, bars, beatsPerBar, tempo, channels: Record<string, Note[]> }`; `Note = { at, duration?, data? }`; `data` is `Json`.
- Notes lie within the loop: `at + (duration ?? 0) <= length` (ticks). `length = bars * beatsPerBar * 96`.
- The library never mutates anything the caller passed in (inputs may be frozen).
- Transport defaults: `lookahead = 0.1`, `interval = 0.025`, `startDelay = 0.05` (seconds).
- Start-only events; no `stop` events; no tempo override; no cancel of already-emitted notes.
- Package names `@loops/core`, `@loops/web-audio`, `@loops/react`; demo at `examples/drum-machine`.
- Strictly test-first: a failing test is run and seen to fail before its code is written.

## Review Focus

Inputs the spec implies but its behavior lists don't exercise. Each has a pinning test in the owning task (marked ★).

1. A channel id of `"__proto__"` (or `"constructor"`) arriving through `JSON.parse` must round-trip as an ordinary channel and never pollute prototypes. ★ Task 2.
2. React re-renders hand `setLoop` the *same* loop object over and over; that must be a no-op (no re-anchor, no notification, no snapshot change). ★ Task 7.
3. A stalled timer (background tab; 1 s between pumps) must catch up by emitting every due note in order, flagged `late`, dropping none. ★ Task 7.
4. A tempo slider drag fires dozens of `setLoop` calls inside one pump interval; the result must equal a single `setLoop` with the last value, with no time drift. ★ Task 8.
5. An empty loop, a channel with `[]`, and `start()` before any loop must play silently without errors. ★ Tasks 6, 7, 8.

## Decisions made while planning

Calls the spec left open. All are easy to change:
- Tempo bounds are `MIN_TEMPO = 20`, `MAX_TEMPO = 400`.
- `parseLoop` rejects unknown keys on a loop or a note (diagnostic path = the key). Channel ids keep insertion order; only notes are sorted and per-object key order is fixed.
- Edit helpers throw `RangeError` on invalid arguments. They return the *same* loop object when nothing changes.
- `clearChannel` empties the channel and keeps its key. `steps()` ignores whitespace and `|`.
- `setLoop` always applies at `scheduledUpTo` immediately, in every status. There is no deferred "pending loop".
- Pausing leaves already-emitted lookahead notes playing; resume continues from `scheduledUpTo`.
- With no loop, a playing transport advances `scheduledUpTo` silently at 120 bpm. `getPosition()` is `null` until a loop is set.
- Window ends are `Math.floor(tickAt(now + lookahead))`.
- `onError` default is `console.error`. `usePlayhead` has no latency option in v1.
- Package `exports` point at TypeScript sources (`./src/index.ts`). Publish builds are out of scope. Fakes ship as `@loops/core/testing`.

### Task 7: `testing` fakes and `transport` basics

**Files:**
- Create: `packages/core/src/testing.ts`, `packages/core/src/transport.ts`, `packages/core/test/transport.test.ts`
- Modify: `packages/core/src/index.ts`

**Interfaces:**
- Consumes: `Loop`, `Note`, `compileLoop`, `queryWindow`, `TempoAnchor`, `createAnchor`, `timeAt`, `tickAt`, `reanchor`, `ticksToSeconds`, `loopLength`.
- Produces in `transport.ts` (spec §7.6 verbatim):
  - `interface Clock { now(): number }`, `interface Timer { every(ms: number, fn: () => void): () => void }`
  - `interface NoteEvent { channel: string; note: Note; time: number; duration?: number; tick: number; late: boolean }`
  - `interface TransportSnapshot { status: "stopped" | "playing" | "paused"; loop: Loop | null }`
  - `interface TransportOptions { clock: Clock; timer: Timer; lookahead?: number; interval?: number; startDelay?: number; onError?: (error: unknown, info: { channel: string }) => void }`
  - `interface Transport { subscribe(l: () => void): () => void; getSnapshot(): TransportSnapshot; getPosition(at?: number): { tick: number } | null; setLoop(loop: Loop): void; start(): void; pause(): void; stop(): void; dispose(): void; channel(id: string, handler: (e: NoteEvent) => void): () => void }`
  - `function createTransport(options: TransportOptions): Transport`
- Produces in `testing.ts` (exported as `@loops/core/testing`):
  - `interface FakeEnv { clock: Clock & { set(t: number): void; advance(s: number): void }; timer: Timer & { activeCount: number; lastMs: number | null; fire(): void }; run(seconds: number, step?: number): void }`
  - `function createFakeEnv(): FakeEnv`. `run` advances the clock in `step` increments (default 0.025) and calls `fire()` after each; `fire()` calls every active callback once.

Algorithm (not fixed by the signatures). State: `status`, `compiled`, `anchor`, `originTick`, `scheduledUpTo` (absolute tick up to which notes are emitted). On each pump while playing: `horizon = Math.floor(tickAt(anchor, now + lookahead))`; if `horizon > scheduledUpTo`, query `[scheduledUpTo, horizon)`, emit each hit to its channel's handlers with `time = timeAt(anchor, absTick)`, `duration = ticksToSeconds(note.duration, anchor.bpm)` when present, `late = time < clock.now()`, then set `scheduledUpTo = horizon`. `start()` from stopped sets `anchor = createAnchor(0, now + startDelay, bpm)`, `originTick = 0`, `scheduledUpTo = 0`, and registers the timer at `interval * 1000` ms (default bpm 120 when no loop). `pause()` cancels the timer and freezes position at `scheduledUpTo`. Resume re-anchors at `scheduledUpTo` with `time = now + startDelay`. `stop()` resets to tick 0 from any state. Snapshot objects are replaced only when `status` or `loop` changes. `setLoop` is built in Task 8; in this task it only stores the loop, compiles it, and notifies (identity-equal loops are a no-op).

- [ ] **Step 1: Write the failing tests** in `transport.test.ts`. Fixture: `L` = 1 bar 4/4 at 120 bpm, `kick` at 0 and 192, `snare` at 96; `env = createFakeEnv()`. Time of tick `t` after `start()` at clock 0 is `0.05 + t * 60 / (120 * 96)`.
  - Initial: `getSnapshot()` is `{ status: "stopped", loop: null }`; `getPosition()` is `null`.
  - `setLoop(L)` notifies subscribers once and updates `getSnapshot().loop`. ★ `setLoop(L)` again with the same object: no notification and `getSnapshot()` returns the same reference.
  - `start()` then `env.run(2.1)` delivers `kick` at time 0.05, `snare` at 0.55, `kick` at 1.05, then `kick` at 2.05, each with `late: false` and `tick` 0/96/192/0; `event.note === L.channels.kick[0]` (identity). `env.timer.lastMs` is 25.
  - A note `{ at: 0, duration: 24 }` at 120 bpm yields `event.duration` 0.125.
  - A handler that throws: another handler on the same channel still receives the event; `onError` is called with `(error, { channel })`; playback continues. Channels with no handler drop events; the unsubscribe function stops delivery.
  - `pause()` sets status `paused`, cancels the timer (`activeCount` 0) and emits nothing further; `start()` resumes. Across `start → run(0.3) → pause → run(1) → start → run(2)`, no `(channel, time)` pair is delivered twice, and times are strictly increasing per channel.
  - `stop()` from playing, from paused (dilla regression) and from stopped all give status `stopped` and `getPosition()` `{ tick: 0 }`; `start()` after `stop()` emits the kick at tick 0 again.
  - `start()` while playing and `pause()` while not playing are no-ops (timer registered once).
  - ★ `start()` with no loop: status `playing`, no events, no errors; calling `setLoop(L)` afterwards begins emitting events.

Algorithm (not fixed by signatures). `setLoop(loop)` applies **immediately at `B = scheduledUpTo`**, in any status. In order: (1) if `loop.tempo` differs from `anchor.bpm`, `anchor = reanchor(anchor, B, loop.tempo)`; (2) if a previous loop existed with a different length, let `r = mod(B - originTick, oldLength)`, `r2 = r mod newLength`, `originTick = B - r2` (with no previous loop, `originTick` stays); (3) store `compiled = compileLoop(loop)`; (4) replace the snapshot and notify.
